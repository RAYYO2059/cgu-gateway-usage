## 門檻與執行完整性

Opus（`claude-opus-5`）與 Codex（`gpt-5.6-sol`）各完成 600/600，最終輸出均無缺列、重複 sha256、樣本外 sha256 或非零外部工具事件。兩側 domain 完全相同 **495/600（82.5%）**，達到 [事前凍結的 0.75 門檻](../ref/FREEZE_2026-09.md)。分流層的 53.4%（n=58）僅作背景參照，不參與此門檻。上限校準的 Opus 自我一致率參照是 22/25（88%，判讀精度 ±8pp）；82.5% 與該小樣本參照接近，但不能由此推出分類正確率。

兩側的逐筆 user prompt 均由同一 `build_prompt()` 產生，字元上限 1,200、字典渲染與 JSON schema 相同；模型、CLI 與執行端固有的 host instructions 不同。Opus 本地請求設定指紋為 `2f651b15de5086693cf30afc37385e2c360eba759b912ea8ddd5b6f2cfc12490`；Codex 提示詞配方指紋為 `0676d93e4dba38b5e52eaaae2eedd6d8ee2c9b0bd44693eb146009cfcf393e1c`，執行指紋為 `7d1928d7c3718cebf83a14a3830362615fba8a46ca3d132978d0c2e6c8af6bb2`（`codex-cli 0.153.4`）。兩側指紋的涵蓋範圍不同，不能以雜湊值不同推論 user prompt 不同。

正式 600 筆中有 **281 筆（46.8%）**在 1,200 字元截斷。Opus 最終輸出失敗 0、工具事件 0；Codex 最終輸出失敗 0、工具事件 0。Opus `prompt_tokens_total` 最小值 **3,158**，缺值 0。Opus 成功列的 CLI 回報估算成本合計 **US$23.680861**；先前未寫入結果的失敗嘗試不在此數，且此數不併入資料集牌價等值成本 US$2,749.32。

`named_third_party=true`：Opus 23 筆、Codex 29 筆、交集 16 筆。這是模型標記的計數，沒有人工核對；本檔與彙總程式都不輸出內容、sha256 或來源路徑。

## 分層加權的暫定分布

樣本依 `unit_type × 內容長度帶` 的 12 個實際分層抽取，長度切點為 251／986／4,799，每層先保底 15。下表對相異內容用每筆的 `sample_weight` 求和；對請求先乘 `n_requests` 再求和。「請求占比」以各值的加權請求估計除以全部值的加權請求估計，並非把抽樣列的請求數直接除以 58,100。

| clinical | 1,093.21 | 6.3% | 1,152.81 | 1.9% |

已知 eligible 母體有 **58,100 筆請求**；加權請求原始估計合計 61,466.14，較已知總數高 3,366.14（5.8%），是抽樣估計誤差，不可把表內估計請求數稱作已觀測的全體請求數。上述占比是比值估計，尚未計算抽樣誤差區間，也沒有校正模型分類誤差。尤其 1,200 字元截斷 281/600，且 lite 的 `prompt_text` 不能代表完整請求，限制仍在。

## `not_applicable` 事前預期為零：尚未釐清

[凍結檔](../ref/FREEZE_2026-09.md)事前預期 0，實際 Opus **13/600**（對應 45 筆請求），不能因交叉一致率過門檻就視為正常。其中 Codex 也判 `not_applicable` 9 筆，另外 4 筆判 `infrastructure`；13 筆的 Opus `confidence` 為 high 1、medium 12、low 0。

使用原有 `prefilter.build()` 對這 13 個 sha256 重算：13 個都在「需送分類器」母體，既有向量化、影像、工具自動發出、流程中繼四條命中旗標均為 0，且無多規則命中。這排除了把**已被既有規則命中的內容誤放回樣本**的情形；仍無法區分「現有規則漏抓一種未定義形式」與「模型把 `not_applicable` 用於本應標其他值的內容」。本輪沒有查看這些筆的原文，也沒有用模型結果改寫前置規則。異常解除前，加權分布只作探索性估計，不進主要交付報告。
