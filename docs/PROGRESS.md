## 三、成本

牌價等值成本合計 **US$2,749.32**。定義為 token 用量乘以 OpenAI 公開牌價，
非實際帳單。取價日為 2026-08-27，價目與每個價位的可靠度見
[pricing_table.csv](../ref/pricing_table.csv)。

完整表格：[cost_by_unit_lite.csv](data_lite/cost_by_unit_lite.csv)、
[cost_structure_lite.csv](data_lite/cost_structure_lite.csv)

**成本結構**

| 項目 | 佔比 |
| --- | --- |
| 未快取 prompt | 30.73% |
| 快取讀取 | 28.46% |
| 快取寫入 | 18.76% |
| 輸出 | 22.05% |

快取相關合計 47.22%。成因為 agent 型客戶端每輪重送完整對話歷史，
**88.30% 的 prompt token 為快取讀取**。此為使用模式造成的成本結構，
非模型單價。機制的量測見 [RESULTS.md](RESULTS.md)。

**請求數與成本的分布不一致**

服務憑證佔 49.85% 的請求、18.03% 的成本（每筆 $0.0083）；教職員佔 18.69%
的請求、38.37% 的成本（每筆 $0.0468）。其餘五個單位的成本／流量倍率落於
1.20–1.63。

教職員與服務憑證的每筆成本差異 5.68 倍可拆為兩層：服務憑證有 68.9% 的請求
使用本地模型（自建部署，不計費）造成 3.16 倍，模型組合差異造成 1.80 倍。
兩者的每筆 token 數差異為 0.06%。

服務憑證的「68.9% 使用本地模型」與該列在表中被抑制的原因（單一識別碼佔該
單位 68.9% 的請求）**是同一批 41,397 筆請求**——一個自動化流程既主導了該
單位的流量，也決定了它的成本結構。

**計價涵蓋率**

有價目的請求涵蓋 97.77% 的 token。未計價分三類：本地模型（42,067 筆，
自建部署不經計費）、非 token 計價端點（558 筆，按張或按秒計價）、
無價目模型（230 筆，token 為 0，無可計價用量）。
見 [cost_coverage_lite.csv](data_lite/cost_coverage_lite.csv)。

## 四、使用類型（進行中）

**已完成**：母數界定（120,520 筆 → 33,666 個相異內容 → 20 字元下限後
31,011 → 四項前置規則排除後 17,365 個需分類）、三軸分類架構、
150 筆人工驗證集。

**未完成**：人工標註、分類器執行、準確率驗證。

**已知的一項結果**：原提問之三類別（行政、程式開發、文獻檢索）在 209 筆
探索樣本（59 + 150）中的命中為 0、3、0。

行政類別 0 筆之成因為管道限制：本 gateway 僅提供 API 介面，無網頁介面，
使用者需具備程式呼叫能力。此為介面條件，非使用行為之推論。

樣本中出現頻率最高的類型為教學內容生產流程（課綱萃取、逐句授權審查、
三方比對覆核、自動命題、誘答設計、卡片品質審核）。在 150 筆驗證集中佔
32 筆（21.3%），為七支已識別流水線中最大的一支（佔已識別的 68 筆之 47.1%）。
該類型不在原提問的三個類別內。

已識別的流水線僅覆蓋驗證集的 45.3%，且該數字是**下界**：只跑過一次的流水線
在樣本中與一次性提問無法區分。
