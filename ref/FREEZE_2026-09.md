## 軸間約束與評估門檻

`must` 是定義上的必然，檢查指令遵循；實際輸出只要不等於指定的
`axis_level` 就算違反，`unsure` 也不算符合。逐群計數並回報違反，不計比例。

| 強度 | `disposition` | 要求／預設的 `axis_level` | 定義 |
| --- | --- | --- | --- |
| must | `tool_injected` | `none` | 該群將移出分類母數，axis_level 問的問題對它不成立 |
| must | `service_relay` | `not_attributable` | 意圖屬於不使用本 gateway 的第三方，載荷不判 role/domain |
| must | `insufficient` | `insufficient_data` | 材料不足以判定這一群，就不足以判定任何一軸 |
| default | `batch_project` | `all_three` | 外框載明用途時用它；前綴看不出 role/domain 時改填 invocation_only |
| default | `user_envelope` | `invocation_only` | 載荷要另外抽樣才判得出 role/domain；外框已載明時可填 all_three |

`default` 是典型情況而非硬約束，評估時對每一對都計算兩個方向，並各自
標明分子與分母：

- `P(axis_level = X | disposition = Y)`
- `P(disposition = Y | axis_level = X)`

兩個方向皆至少 95% 為通過；任一方向落在 90%（含）至 95%（不含）為
「要看，但不擋」；任一方向低於 90% 為「這一批判定不可信」。任一方向的
分母小於 `MIN_GROUP_SIZE` 時不算百分比，只報原始計數。

## 人工盲標的判讀規則

本節在人工盲標開始前寫定；版本庫中的提交時間戳是預先註冊的證據。本節只補齊
判讀與退回門檻，不改動前述 taxonomy、提示詞、本地請求設定指紋或評估軸。

逐類的人機一致率依下列門檻判讀：

| 一致率 | 判讀 |
| ---: | --- |
| `< 0.70` | 該類模型判定不可用 |
| `0.70 ≤ 一致率 < 0.85` | 該類只能用於粗分類，不出細分比例 |
| `≥ 0.85` | 該類可報，仍須附混淆矩陣 |

加權整體一致率若 `< 0.70`，整批分流結果不進報告。`insufficient` 的人工盲標
樣本 `n=1`，不論結果如何都只出計數。

分層抽樣的逐類一致率可直接讀。整體一致率必須用母體各類群數
`158 / 37 / 12 / 10 / 1` 加權；未加權的整體數字沒有判讀意義。若兩種數字
因稽核需要並列，必須分別標明「母體權重加權」與「樣本未加權」及各自算法，
不得讓兩者看似可直接比較。

`service_relay` 的母體 `n=10`，剛好等於 `MIN_GROUP_SIZE`，比例可報，但必須
同時標明一群等於 10 個百分點。

人工標註者的自我一致率是發布人機一致率的前置條件：58 群完成後至少間隔
3 天，再從這 58 群以固定且另行記錄的隨機種子抽 15 群盲重標。自我一致率
若 `< 0.80`，退回修改字典，且不得發布任何模型一致率數字；標註者自己的
穩定度是人機一致率可解讀的上界。

## Domain 逐筆判定的交叉一致率門檻

本節在 domain 逐筆判定與抽樣執行前寫定；版本庫中的提交時間戳是預先註冊的
證據。比較單位是本輪固定抽出的 600 個相異 `prompt_text_sha256`，只比較
Opus 與 Codex 的 `domain`，不把 `named_third_party` 或 `confidence` 納入
通過條件。

交叉一致率的分母固定為 600；只有兩側 `domain` 完全相同才計入分子。任一側
呼叫失敗、輸出不符 schema，或該次呼叫出現非零工具事件，均不計入分子，並
另列失敗或可疑事件計數，不得從分母排除。交叉一致率 `>= 0.75` 才繼續；
若 `< 0.75`，則依分流層相同方式記入 `CLASSIFICATION_LIMITS.md`，domain
分類結果不進報告。此門檻不得依事後結果修改。

只用來說明先前分流層的結果，不參與 domain 門檻計算。
